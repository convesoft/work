## Scope

Add the MCP adapter for the existing shared operations. Reuse semantic input, result, validation, and error handling from the core. Define transport/tool schemas in Mara and select an appropriate supported MCP transport during implementation.

The dependency on the CLI task establishes a sequential bootstrap order and a concrete behavior reference; MCP must call the shared core, not shell out to the CLI.

## Acceptance criteria

- MCP exposes the same durable-item and readiness operations as the first CLI slice.
- Equivalent requests against equivalent fixtures produce the same content, graph state, and failure meanings after transport envelopes are normalized.
- Tool schemas distinguish absent optional fields from invalid null or wrong-type values.
- The create → depend → ready → close → ready loop works through MCP.
- Integration tests cover successful calls, invalid input, source errors, and worktree selection through an actual protocol client.
- Neither adapter contains an independent implementation of the graph or storage rules.

## Mara contracts

`REQ-CLI-MCP-PARITY`, `DES-INTERFACE-ADAPTERS`, `VER-SURFACE-PARITY`, and `REQ-BOOTSTRAP-COMPATIBILITY`.

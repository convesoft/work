## Scope

Implement item discovery, parsing, metadata validation, and lookup in the selected checkout's .work/items directory. Adopt the authored backlog directly rather than importing it into a separate store.

Keep body bytes separate from the parsed header. The JSON Schema is a reference artifact for header shape; use an appropriate Rust implementation without requiring a particular validation library.

## Acceptance criteria

- Every real bootstrap item can be loaded from an isolated copy with its canonical ID and original body bytes.
- Manual state, aggregate state omission, defaults, optional hints, labels, and closure reasons follow version 1.
- Full IDs and unambiguous displayed prefixes resolve; ambiguous prefixes return an error.
- Duplicate IDs, filename mismatches, invalid UUIDv4 values, duplicate YAML keys, unknown keys/versions, forbidden YAML constructs, and wrong types receive useful file-level diagnostics.
- LF and CRLF framing work, and body-leading blanks and final-newline choices remain intact.
- Loading does not rewrite files or require SQLite.
- An invalid file is available for inspection; it is not silently omitted from an apparently valid project view.

## Mara contracts

`DES-ITEM-FORMAT`, `DES-FILE-LAYOUT`, `REQ-OPAQUE-BODIES`, `REQ-BOOTSTRAP-COMPATIBILITY`, and `VER-ITEM-IDENTITY`.

See [item format](../../docs/item-format.mara.md) and [frontmatter schema](../../docs/schemas/work-item-v1.schema.json).

## Scope

Define the scope/filter schema and implement one atomic operation that selects and claims a ready item from the selected checkout. Preserve accepted priority and ID ordering; scope this to version items without a new product concept.

## Acceptance criteria

- Scoped list and claim-next use the same selected-view graph and explicit filters.
- Claim-next reloads the selected graph and claim files, selects by priority 0–4 then canonical ID, and publishes exactly one eligible claim while holding the shared lock. Specify source-change conflict handling and checkout-lock ordering.
- Concurrent CLI/MCP callers cannot receive the same coordination identity, including when notifications are absent or missed; no eligible work returns a structured empty result.
- CLI and MCP expose matching filters, errors, and readiness explanations with race and worktree-view tests.

## Implementation boundary

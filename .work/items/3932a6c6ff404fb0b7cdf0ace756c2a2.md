## Scope

Prepare the intentional 0.1.0-beta.2 release only after its implementation aggregate is merged and accepted. Package identities, supported hosts and licensing remain governed by ADR-WORK-DISTRIBUTION; this item does not authorize publication.

## Acceptance criteria

- All beta.2 implementation children are merged and accepted; beta.1 execution migration/compatibility is not a prerequisite.
- Select one final main revision, intentionally align Cargo/npm version metadata and generate the changelog in a separate release-preparation PR; do not trigger preparation during architecture authoring.
- Verify source/Mara, packaged CLI/MCP beta.2 acceptance and installed artifacts on all declared supported hosts at that exact revision, recording artifact hashes and limitations.
- Verify actual required CI protection, GitHub release-environment approval and all npm trusted-publisher settings; workflow YAML is not evidence of external settings.
- With separate explicit publication authority, create/verify an immutable annotated tag, publish matching native packages then dispatcher, verify public install and publish the GitHub release.
- Partial publication retries only the same approved revision/matching artifacts. Keep this item open until publication evidence satisfies acceptance.

## Mara contracts

ADR-SCOPE-OWNED-EXECUTION, REQ-BETA2-BOUNDARY, VER-BETA2-SURFACES, ADR-WORK-DISTRIBUTION; follow docs/delivery.mara.md.

## Authority

No push, PR merge, tag, protected approval, external-settings mutation, workflow dispatch or package publication is authorized by backlog creation.

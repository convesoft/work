## Scope

 Define run manifest and temporary item file contracts, one-run-per-root behavior, repeated template applications, provenance, and atomic/retryable publication under the Git common directory. Integrate temporary items into graph inspection and lifecycle operations.



 ## Acceptance criteria

 - One root item has one shared run; duplicate start identifies that run or reports a clear conflict.
- Temporary files are authoritative; a complete template graph becomes visible together, including dependencies and provenance.
- Interrupted or concurrent publication can be retried without duplicate or partially actionable work.
- Linked worktrees inspect the same run, while durable checkout views remain selected locally; CLI/MCP and restart tests cover the complete loop.

 ## Mara contracts

 `REQ-EPHEMERAL-WORK`, `REQ-EPHEMERAL-FILES`, `REQ-RUN-ATOMICITY`, `REQ-SINGLE-RUN`, `DES-TEMPLATE-RUNS`, `RISK-FILE-DB-CONSISTENCY`. Resolve any unsettled operation or storage details in [open questions](../../docs/open-questions.mara.md) and update canonical Mara knowledge before implementation.

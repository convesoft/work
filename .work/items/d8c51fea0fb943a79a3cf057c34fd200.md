## Scope

Define separate `run.yaml`, `items/<id>.md` and `applications/<id>.yaml` contracts, one-run-per-root behavior, repeated template applications, provenance, and atomic/retryable publication under the Git common directory. Integrate temporary items into graph inspection and lifecycle operations.

## Acceptance criteria

- One root item has one shared run; duplicate start identifies that run or reports a clear conflict.
- Each run, item and template application has its own authoritative file. The manifest does not embed all entities; a committed publication boundary exposes the complete graph and provenance together.
- Staged operation files and idempotency records make interrupted/concurrent publication retryable without duplicate or partially actionable work; locking alone is not treated as crash-atomic publication.
- Linked worktrees inspect the same run, while durable checkout views remain selected locally; CLI/MCP and restart tests cover the complete loop.

## Mara contracts

`REQ-EPHEMERAL-WORK`, `REQ-EPHEMERAL-FILES`, `REQ-RUN-ATOMICITY`, `REQ-SINGLE-RUN`, `DES-TEMPLATE-RUNS`, `DES-ENTITY-LIFECYCLES`, `DES-FILE-COORDINATION`, `RISK-FILE-DB-CONSISTENCY`. Resolve any unsettled operation or storage details in [open questions](../../docs/open-questions.mara.md) and update canonical Mara knowledge before implementation.

## Scope

Define separate run manifest and wisp files with workspace references, one-current-run-per-root behavior, and ordinary template expansion. After a run is finalized/disposed, allow a new run for the same root with a fresh ID. Implement the specified template version-2 format/preview extension with a per-item material/wisp selector and version-1 compatibility. One template may mix both: material items go to the selected checkout `.work/items/`, wisps to run `items/`; material-only planning requires no run. Create no application records, retry keys or transaction engine. Resolve normal material-item reads and mutations through its associated worktree, using that whole file as the authority. Store material changes there immediately; no separate material-state overlay or end-of-run flush.

## Acceptance criteria

- One root has one current shared run; duplicate start identifies it or reports a conflict, even when it is finished but unfinalized. After finalization/disposal, a fresh run can start; racing starts still select one current run without resurrecting old wisps or changing root completion.
- Each run and wisp has its own authoritative file. Shared references identify associated worktrees; material state stays in the actual item files, with no duplicate run-owned state or aggregate entity snapshot.
- Mixed-template CLI/MCP creation places material items and wisps correctly, preserves ordinary relations, and returns permanent IDs mapped from preview keys. Material-only expansion creates no run.
- Validate prospective inputs/graph before writes. On an injected failure after three of five creations, preserve/report known created files; the caller can inspect, remove the partial result and retry. No application record, rollback or deduplication guarantee is introduced. Ordinary graph diagnostics remain applicable.
- Normal queries from linked worktrees resolve an associated material item to its actual worktree file, including uncommitted body/metadata/relationships/state. Show the source path; explicit branch-local inspection remains available. Missing associated sources are reported without stale-main fallback. CLI/MCP and restart tests prove material mutations persist immediately and run disposal does not reset them or erase needed source associations.

## Implementation boundary

Implement template version 2 exactly as `DES-RUN-API`: per-item persistence default material, root optional unless referenced, no implicit run creation. Implement creation/membership/expansion, not squash/discard. Load terminal run fixtures to prove fresh later starts; the dependent finalization item owns terminal transitions. Main owns basic source bindings/resolver and all shared adapters.

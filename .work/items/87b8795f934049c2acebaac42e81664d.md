## Scope

Establish a minimal Rust library and executable structure for shared operations and thin CLI/MCP adapters. Inspect the repository before choosing crates or module boundaries; the task does not prescribe a multi-crate workspace.

Start from the prepared baseline on main in a dedicated feature branch. Repository initialization and the baseline commit precede this item.

Add the first CI and release workflows together with the buildable Rust foundation. Follow [the delivery conventions](../../docs/delivery.mara.md): CI on PRs to main and pushes to main, release verification on main changes to CHANGELOG.md, and protected publication. Keep CHANGELOG.md out of this change; the separate release-preparation item owns the first candidate. Record unresolved distribution choices explicitly before implementing package-specific publication.

Implement read-only Git project discovery from the current location or an explicitly selected worktree path.

## Acceptance criteria

- A Cargo project builds and its applicable formatting and tests pass.
- Shared operation code can be called without launching either interface.
- Discovery identifies the selected worktree root and resolved Git common directory, including linked worktrees whose .git entry is a file.
- Selecting another worktree does not switch branches or change the caller's checkout.
- Non-Git directories and bare-only repositories return an explicit unsupported-project error.
- Discovery does not initialize Work runtime state, spawn agents, or create worktrees.
- The source tree documents how to run the current build and tests.
- The Rust toolchain is pinned and Cargo.lock is committed.
- CI runs formatting, Clippy, tests, and complete Mara schema/project validation using a pinned Mara version. The initial PR provides actual CI evidence.
- Initial release infrastructure keeps verification separate from protected publication, captures one source revision, and documents required external configuration. Its implementation is checked without creating a release candidate or publishing packages.
- Unimplemented CLI/MCP behavior is not reported as passing release smoke coverage. Packaged end-to-end checks are completed as those interfaces become available, before release preparation can pass.
- No generated changelog, release tag, or package publication is included in this foundation change.

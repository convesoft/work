## Scope

Define cleanup-target and retry protocol using the workspace entity file and operation-scoped recovery metadata. Represent removal as an ordinary explicit Work item; external tooling performs physical Git worktree deletion and reports the result.

## Acceptance criteria

- Cleanup checks active executions, shared workspace users, unfinished work, and retained commits/results/handoffs before allowing removal.
- Marking the workspace file as closing under the shared lock rejects new assignments; failure retains inspectable context and supports retry. The lock is not held across external worktree deletion.
- Successful external removal clears operational workspace records without implicitly deleting work from claim release, session removal, or run finalization.
- CLI/MCP and recovery tests cover interruption before and after physical deletion.

## Mara contracts

`REQ-WORKSPACE-CLEANUP`, `DES-WORKSPACE-ASSOCIATIONS`, `DES-ENTITY-LIFECYCLES`, `DES-FILE-COORDINATION`, `REQ-HANDOFF-CONTEXT`. Exact interfaces: `DES-CONTEXT-API`, `DES-EXECUTION-IO`. Follow [the prepared handoff](../handoffs/beta-execution.md); new material decisions still require Mara updates before code changes.

## Implementation boundary

Use the existing workspace closing/cleanup mapping and begin/report/cancel verbs in `DES-CONTEXT-API`. External tools remove the checkout; source bindings must be transferred explicitly before cleanup.

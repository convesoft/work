## Acceptance criteria

- Fresh ordinary Git repositories, their linked checkouts and detached primary checkouts resolve the actual primary host. Separate Git directories are explicitly unsupported and refuse without writes under the user-approved hosting contract. Initialization never runs Git init, creates a synthetic task, starts an agent or changes external Git/worktree state.
- Prepare necessary Work directories and coordination, initialize exactly one active standing root run and append only missing exact housekeeping rules to the primary checkout's `.gitignore`, preserving existing bytes and unrelated rules. Healthy repeat preserves run identity and is unchanged when preparation is complete; repairing a missing ignore rule may change configuration without rotating the run.
- Fresh material CRUD and material-only template planning require no execution initialization. Missing catalogs are empty for reads; valid material writes prepare only necessary directories/locks after candidate checks and create no scope anchor/default run merely to plan.
- Root initialization freezes ignore-file before/after fingerprints in its operation-specific start plan. Continuation retains the exact run/anchor/configuration targets; conflicts preserve artifacts/partial evidence. Persisted execution with missing coordination is not silently repaired.
- Status implements the frozen execution inspection states, root ID, coordination flag, pending records and source-linked diagnostics. It writes nothing, handles malformed progress and terminal-root inconsistencies honestly, and does not equate usable infrastructure with item readiness or a running agent.
- CLI/MCP parity, invalid-input no-write behavior, concurrent init, interruption/restart, user-edited ignore conflicts and primary/linked fixture isolation are tested through real public calls. Documentation remains explicit about unimplemented downstream operations.
- Run applicable Rust checks, wire consistency, complete Mara validation and Work diagnostics. Required local review, squash integration and verification at the actual scope SHA precede closure.

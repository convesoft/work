## Scope

Define separate run-scoped YAML session files and independent shared YAML workspace records. Store association/default/override references with one authoritative owner; do not embed registries inside a run or claim. Keep execution and physical worktree creation external; one-time workers need no named registration.

## Acceptance criteria

- A claim can reference an optional run-scoped session and reusable workspace record.
- Session removal or claim release does not delete the worktree or erase useful workspace context. Named files survive individual item completion and are removed by successful run finalization; shared workspace files follow their own cleanup lifecycle.
- Selected-worktree identity and a surviving checkout are represented without treating a shared index as durable truth.
- CLI/MCP operations and tests cover reuse, multiple users, restart, and cleanup eligibility.

## Mara contracts

`DES-CLAIM-CONTEXT`, `DES-ENTITY-LIFECYCLES`, `DES-FILE-COORDINATION`, `DES-WORKSPACE-ASSOCIATIONS`, `REQ-WORKTREE-VIEWS`, `REQ-EXTERNAL-EXECUTION`. Exact interfaces: `DES-CONTEXT-API`, `DES-EXECUTION-IO`, `DES-RUN-API`. Follow [the prepared handoff](../handoffs/beta-execution.md); new material decisions still require Mara updates before code changes.

## Implementation boundary

Extend the already established workspace/binding format; do not create a parallel registry. Deliver reusable workspace management and named-session operations in `DES-CONTEXT-API`. Basic material-source registration/resolution is already part of claims/run coordinator integration.

## Scope

Define shared handoff envelopes and recoverable save/read/cancel/cleanup operations. Store each handoff as its own Markdown file in shared `handoffs/`, with caller-authored context for one or more receivers, including continuation on the same item. Handoffs may outlive their source run.

## Acceptance criteria

- Inspection and claiming expose incoming context verbatim, including multiple sources and receivers.
- Closing a source, releasing or reassigning a claim, or failed completion retains context while receiver obligations remain.
- Automatic cleanup waits until all receiver obligations resolve; cancellation counts, and reopening does not resurrect deleted notes.
- Concurrent receiver changes and interrupted publication with completion/claim release are recoverable under the shared lock and narrow multi-file protocol. CLI/MCP and restart tests agree; cross-run receivers prevent premature run cleanup.

## Mara contracts

`REQ-HANDOFF-CONTEXT`, `DES-HANDOFF-RECORDS`, `DES-ENTITY-LIFECYCLES`, `DES-FILE-COORDINATION`, `REQ-OPAQUE-BODIES`. Exact interfaces: `DES-CONTEXT-API`, `DES-EXECUTION-IO`, `DES-CLAIM-API`. Follow [the prepared handoff](../handoffs/beta-execution.md); new material decisions still require Mara updates before code changes.

## Implementation boundary

Use the exact handoff frontmatter, opaque body, receiver updates and pruning operations in `DES-CONTEXT-API`. Coordinate save-before-close-before-ending through main-owned item mutation wiring, with explicit partial results and no general transaction engine.

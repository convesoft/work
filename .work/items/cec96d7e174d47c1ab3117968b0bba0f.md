## Scope

Implement shared create, inspect/list, metadata-update, relationship-add/remove, close, and reopen operations using the reader and graph evaluator. Specify the operation result/error contracts in Mara before making the adapters depend on them.

Use recoverable file replacement and conflict detection appropriate to the mutation. Preserve existing files on rejected operations; do not claim arbitrary multi-file atomicity merely because a database transaction is available.

## Acceptance criteria

- Creation uses UUIDv4 canonical identities and never overwrites an existing file.
- Metadata and relationship edits preserve all existing body bytes.
- Every successful graph mutation leaves a valid graph; rejected input and conflicting edits leave original content intact.
- Relationships use full IDs and are stored once with derived reverse views.
- Close records done with an optional opaque reason; reopen clears the reason, recomputes readiness, and does not reopen completed downstream manual work.
- Aggregate completion stays derived; ordinary close/reopen cannot write a cached aggregate state.
- Inspection and explicit repair remain possible when direct file edits created an invalid graph.
- Tests cover failures around publication and changed-on-disk input.
- These operations do not launch agents, run PR/CI actions, or imply claim ownership.

## Mara contracts

`DES-ITEM-FORMAT`, `DES-LIFECYCLE`, `REQ-LOCAL-STATE`, `REQ-OPAQUE-BODIES`, `REQ-GRAPH-INTEGRITY`, and `REQ-EXTERNAL-EXECUTION`.
